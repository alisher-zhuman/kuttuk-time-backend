# Веб-версия для покупателя - план (2026-11-11)

**Зачем** (пользователь 2026-11-11): в Кыргызстане Telegram у многих ассоциируется со спамом и мошенниками - покупателю нужен обычный сайт. Владелец и админ остаются в мини-аппе. Мини-апп для покупателя тоже остаётся.

**Решения пользователя (2026-11-11):**
- покупать можно **без регистрации** - гость;
- вход - **«Войти через Telegram»** на сайте (официальный виджет Telegram): покупки гостя переходят в аккаунт, начинают приходить уведомления бота, те же сертификаты видны в мини-аппе. Логин / пароль не делаем (забывают, сброс, хранение паролей, форма отпугивает); вход по SMS - позже, если понадобится;
- сайт - **режим того же React-приложения** (открыто вне Telegram → только покупательские экраны), не отдельный проект;
- домен купим потом, пока - адрес Vercel (`MINI_APP_URL`). Виджету входа нужен домен в BotFather (`/setdomain`) - делает пользователь, при покупке домена поменять там же.

## Этапы

### 1. Бэк: гость (без Telegram) - **сделано 2026-11-11** (миграция `WebsiteGuests`, тесты `website-guests.int-spec.ts`)
- `users.telegramId` - может быть пустым (гость), `users.guestTokenHash` - sha256 секрета гостя.
- `POST /api/auth/guest` (публичный, лимит по IP): без тела - новый гость → `{ accessToken, guestToken, role }`; с `{ guestToken }` - тот же гость, новый токен. Фронт хранит `guestToken` в `localStorage`.
- Всё, что уже работает по `userId` (заказы, сертификаты, подарки, «Мои сертификаты»), работает для гостя без изменений.
- Для гостя (нет `telegramId`) бот молчит: сообщение о покупке, «на проверке», «деньги возвращены», напоминание о сроке (не «сгорает» - придёт после привязки Telegram), «использован», «подарок забрали». «Подарить» карточкой Telegram гостю недоступно (→ этап 2, ссылка).

### 2. Бэк: оплата и подарок с сайта - **сделано 2026-11-11** (без колонки `orders.channel`: адрес возврата выбирается при создании заказа по `channel` в запросе; адрес сайта - `WEBSITE_URL`, пока он не задан - `MINI_APP_URL`; тесты `website-flow.int-spec.ts`)
- Возврат с Финика на сайт: `RedirectUrl` = `/api/payments/return/<id>/web` → 302 на `<сайт>/orders/<id>` (Финик дописывает `?…` к любой ссылке - поэтому признак в пути, а не в query). Какой возврат - по каналу заказа (`orders.channel`: `telegram` / `web`).
- «Подарить» на сайте: `POST /api/certificates/:id/gift-link` → ссылка `<сайт>/gift/<token>` (та же таблица `certificate_gifts`; новая ссылка заменяет прежнюю незабранную). Фронт открывает меню «Поделиться» телефона (WhatsApp, Instagram, SMS…).

### 3. Бэк: «Войти через Telegram» на сайте
- `POST /api/auth/telegram-widget` - проверка подписи виджета (ключ = SHA-256 от `BOT_TOKEN`, не как у мини-аппа), `request_access=write` - бот сможет писать.
- Если запрос пришёл от гостя - его заказы, сертификаты и подарки переезжают к Telegram-аккаунту (одна транзакция), гость удаляется.

### 4. Фронт: режим сайта (по промпту)
- Вне Telegram: каталог, заведение, оплата, заказ, «Мои сертификаты», подарок; вход гостем автоматически; кнопка «Войти через Telegram»; «Подарить» - меню «Поделиться»; без кабинета и админки (ссылка «Для заведений - откройте в Telegram»).
- Страница доверия: о нас, реквизиты ИП, оферта, контакты (тексты - пользователь).
